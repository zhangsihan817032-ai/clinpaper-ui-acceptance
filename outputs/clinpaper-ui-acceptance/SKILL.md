# ClinPaper UI 样式验收

## 先定位现有网站

每次开始先读 [references/clinpaper.md](references/clinpaper.md) 定位验收网站、Figma、页面映射及部署配置，再读 [references/checklist.md](references/checklist.md) 和 [references/report-contract.md](references/report-contract.md)。

复用同一网站，每次追加一个批次，不另建独立网页。先读正式服务 `/api/review` 与磁盘权威数据；服务不可用时先恢复现有服务，不用空数据覆盖。网站修改与验收结果先进入隔离的本地预览，用户确认具体版本后才发布。不要把截图、账号、病例内容或临时公网地址嵌入 Skill 本身。

## 确定本次范围

- 首次或全流程：覆盖用户指定流程与可访问状态。
- 修复回归：检查指定问题、受影响组件及直接关联页面。
- 新功能增量：检查新增/改动页面、组件与直接关联状态；非本次范围问题不混入本次结论。
- 从用户给定 URL、变更说明、现有报告和 Figma 节点推导范围；只有无法确定且会影响验收时才询问。

只验收视觉样式，不评价数据语义或业务逻辑，不修改产品代码、Figma 或线上业务数据。不要通过确认/提交按钮解锁流程；不可访问的页面明确标记待复核。

## 获取证据并反复核对

使用 Figma MCP 读取当前目标 Frame 的结构、截图和参数；先读取环境中可用的 Figma Skill。使用已有登录态读取实际网页 DOM、计算样式、元素坐标及截图。优先复用可用连接与工具，不假设某个浏览器或工具一定存在。

按 checklist 核对字体、字号、字重、行高、颜色、间距、尺寸、对齐、线条粗细/颜色、圆角。精确数值须有节点或计算样式证据；视觉估测注明估测，不把旧截图猜测当作当前计算值。

至少执行结构检查、参数与像素细查、问题复核三轮。若复核发现新增问题，继续检查后再次完整复核；只有完整一轮没有新增且计划范围已覆盖时才称收敛。记录实际轮次，不预写“已检查若干轮”。缺证据时写待复核，不编造完成。

桌面视口与对应 Frame 宽度一致。移动端有设计稿时完整对照，无稿时只记录可复现的溢出、遮挡、截断、异常断行及控件适配问题。未指定移动端尺寸时用 390×844，发现断点问题时补查 375px、430px。产品移动端与报告网页适配分别记录，不互相替代。

## 增量记录，不覆盖历史

读现有问题后再编号，同一元素同一维度的发现优先追加复核。保留 CP-001–CP-025 及后续问题；新问题按现有最大编号顺延，不能重排、复用或删除。

修复通过需提供实际值、设计值和当次截图；待处理问题验证修复后自动已解决，已解决问题复现后自动待处理。已忽略问题保持原状态并记录复核；未检查的问题不改状态。复核中有新的测量结果时追加记录，原始发现和截图不改写。

每次结果按 report-contract 先在本地预览保存一个批次，服务端生成不可改写的当次快照。正式环境仅在用户确认该版本后增量发布，不整库复制预览数据。批次支持确认后移入回收站、恢复；没有单条问题删除或永久清空。删除批次不连带删问题、状态或其他批次。

## 交付

先使用本地预览副本的 `scripts/publish-run.mjs` 向本地服务追加批次；校验数据和所有图片、统计筛选与跨浏览器状态同步。本地预览使用独立数据库，仅监听回环地址，不改正式网站文件。给用户本地预览链接、变更和验证结果，等待用户明确确认该版本后才上线；这是用户要求的发布规则，不把过去公开分享授权当作新版本确认。

确认后新建正式备份，重新读取线上 revision、状态和编号，再用正式网站脚本增量追加已确认批次。若返回 409，重读当前数据并复核状态与编号，不能盲目更改版本号绕过冲突。不要用预览数据库覆盖线上共享状态，也不要发布本地状态测试。验证公开批次详情、截图与共享状态。

用户要求使用同一固定正式网址，按已配置的稳定托管发布。未配置时说明缺少的主机或托管信息，不把临时隧道称作固定网址；不自动新建或更换隧道，不自动购买域名或创建付费资源。日常用户在正式网站处理问题状态仍即时同步。

每次至少在 1440×900、390×844 检查报告自身的文本、截图、筛选与状态控件。确认前交付本地预览入口和草稿批次链接，明确尚未发布；确认并发布后给同一正式入口、本次批次链接、真实覆盖和未复核项。不要把创建批次说成重新创建网站。

网站缺失且无法恢复备份时，才使用 `assets/site/` 恢复应用程序文件；该模板不含产品数据，不能覆盖现有数据库或批次素材。

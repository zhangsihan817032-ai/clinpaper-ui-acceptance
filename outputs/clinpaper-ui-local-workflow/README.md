# 本地确认后发布

已发布目录：`../clinpaper-ui-style-review/`。当前公网服务直接读取这个目录，开发时不要改动它。

本地预览目录：`../clinpaper-ui-style-review-preview/`。这是同一个验收网站的草稿环境，不是另一个历史记录网站；它有独立数据库，只在本机开放。

## 本地修改与确认

1. 首次运行 `node outputs/clinpaper-ui-local-workflow/prepare-preview.mjs`，复制当前已发布版本和完整状态快照。已存在的预览不会被覆盖；再次准备前先保存未发布修改。复制时不写入线上目录。
2. 运行 `node outputs/clinpaper-ui-local-workflow/start-preview.mjs`，打开 `http://127.0.0.1:8767/index.html#records`。黄色提示条标识本地预览。服务仅监听 127.0.0.1，忽略外部传入的数据库、端口和根目录设置。
3. 后续页面、代码及验收结果在预览目录修改。新批次先使用预览目录的 `scripts/publish-run.mjs` 提交到 8767；保留原始批次草稿 JSON 和截图，用于最终增量发布。预览状态变更不影响线上。
4. 本地验证桌面与移动端、截图、筛选、历史和状态。把本地预览链接、改动范围与验证结果交给用户。用户确认这个版本后才进入发布，不因以前授权公开分享而自动发布新版本。

## 确认后的发布

- 先重新读取正式服务 `/api/review`，备份正式数据库及将替换的代码和资产。确认本地预览后没有追加未经确认的改动。
- 页面代码只发布已确认的差异，移除本地预览提示条；不要整目录覆盖正式环境。服务代码变更需重启时先安排短暂切换与回退。
- 新验收批次通过正式服务的批次接口增量提交。正式共享状态在预览期间可能变化，必须重新核对 revision、问题编号及复核结论；不能覆盖线上数据库，也不能仅改 revision 就强行发布。
- 不把预览中的状态测试、回收站测试或测试批次同步到线上。经确认的验收结论通过 findings 更新状态，未覆盖问题维持线上当前状态。离线副本从正式服务重新生成。
- 图片按批次追加，历史素材不覆盖。验证公网首页、本次批次链接、截图和共享状态后交付同一正式网址。发布失败则恢复原版本；不发布半条验收记录。

## 固定网址

当前没有固定部署账号、主机或域名配置。localhost.run 仅为现有过渡连接，域名可能变化，不能实现固定网址。没有用户指示，不自动新建或更换临时隧道。

固定部署需要持续运行的 Node.js 主机和固定 HTTPS 地址；`data/review.json` 与 `assets/runs/` 必须持久化，单独静态托管无法同步问题状态。接入后将正式地址记录在 Skill 的实例配置中，后续只发布版本，不切换正式网址。

日常用户在正式网页处理问题状态仍即时同步；这里的“确认后发布”适用于网站改动、新验收批次及验收结论。

# 统一设计验收主流程

以目标版本源码与当前设计稿为主要对比材料，用界面图片让设计师核验发现。分别记录源码参数差异、视觉复现、根因判断和修复结论；代码推导不能写成运行实测。

本 skill 是项目内维护的验收规范与参考入口，不代表已经实现各端自动解析器或接通全部仓库、构建环境。

后续工作仅在多项目预览进行，具体入口见 [项目与环境](references/projects.md)。走查、补图、登记、状态维护和报告交付均写入该环境；旧正式站与旧 ClinPaper 预览仅供历史核对，不默认同步或发布。

## 验收操作边界

本节适用于首次验收、全流程验收、增量验收、问题二次验收及截图补证。

- 产品源码和设计稿只读，不修改实现、资源或设计内容。
- 报告写入仅限通过现有报告入口，在本次指定项目内追加问题、证据和复核结论；处理状态按本次任务授权更新，不改其他项目或未授权范围的数据。
- 网站布局、筛选、字段、接口和已有历史记录均不得自行修改。复验追加后续结论，不覆写原始发现、历史快照或归档图片；补证遵循现有追加规则。
- 工具有问题或现有接口无法表达真实结果时，先报告具体问题并保留已完成的验收依据，不擅自修工具、放宽校验或改网站来完成提交。
- 网站优化与工具修复作为独立任务处理，不能由验收授权推定获得修改权限；用户已明确授权的独立任务按其范围执行。
- 问题只使用待处理、已解决、已忽略三种处理状态，不增加“待复核”状态、标签、筛选或统计。依据不足的具体问题保持待处理，缺失依据写入折叠详情，不在卡片正文重复提示；旧接口所需的内部兼容字段见报告契约。

## 首次验收与新功能走查

用户指定项目、端别和版本后，读取对应目标源码并固定完整提交号及设计基线，按以下阶段顺序执行；具体取证要求见下方统一流程。

1. **第一轮：查覆盖。** 列出本次功能的页面、组件、入口、可执行交互及交互前／中／后状态，逐项确认覆盖，包含首页各类卡片；先找遗漏范围，不把只看过页面骨架或默认静态状态当作验收完成。
2. **第二轮：查细节，重复多轮。** 对照设计逐项核对默认态及代码交互后实际生效的样式，包括图标大小与颜色。每轮复扫本次范围、补查上一轮遗漏并去重；发现新问题后继续下一轮，直到完成一整轮且未发现新的具体问题，再进入证据核验。轮数由实际发现决定，不固定为只查一次或凑够三遍；“无新增”只适用于实查范围，不代表绝对无缺陷。权限、源码或设计材料不足时如实列出未覆盖范围，不用空转轮次宣称完成。
3. **第三轮：核验证据。** 逐条核对实现引用及生效条件、设计节点及状态、单位换算、源码位置、双图来源与编号框选，排除误判并合并同一问题。若此阶段发现新的问题或覆盖遗漏，返回相应阶段补查，再核验证据。
4. **最后集中登记。** 前面各轮作为内部检查，不边查边写多个批次；核验完后，把问题及经过核验的证据一次性追加到指定项目网站，沿用已有编号或新增问题。新增问题为待处理；有具体差异但材料不足的候选仍可登记，明确证据限制，由用户决定是否忽略，不能冒充已确认结论。

## 开发修复后的二次验收

用户要求复验、检查修复或二次验收时，默认核验目标源码与当前设计稿是否一致，不以真机、模拟器或运行截图作为通过的前置条件。只复查原问题及直接相关实现，追踪实际引用、资源定义、交互触发、状态变化、条件分支和覆盖关系；原问题位于交互后状态时，必须核对该交互链最终命中的样式。不能仅凭提交说明、变量名或存在点击处理判定修复。

读取用户指定的新发布修复版本并固定完整提交号，取得本项目、本端别及授权范围内的原待处理问题清单，逐条核对各自差异是否消除。比较修改前后代码只用于定位，最终判定仍以新版本实际生效参数与设计要求为准；不能以“代码改过”替代“已经与设计一致”。

- 原问题维度已与设计一致：更新原编号为已解决，依据标为源码验收。
- 仍有明确差异：保持待处理，简述剩余差异。
- 源码、资源或设计依据无法确定：保持待处理，具体疑点放入详情；不增加额外复核状态，也不因缺运行截图推翻已有充分源码依据的结论。

已忽略及未检查的问题不改状态。用户另外要求真机视觉验收时，再取得目标版本运行图；源码结论不冒充运行实测。报告沿用现有问题和界面，按 [报告契约](references/report.md) 控制增量，不因复验追加装饰信息。

## 统一流程

### 1. 固定验收基线

记录项目、端别、目标版本、分支或标签及解析后的完整提交号、设计文件和具体 frame/node、页面与状态。版本由当次任务决定，不默认沿用历史版本。

运行图另记 App 构建号、实际部署或加载的 H5 版本、设备与系统、视口、像素尺寸、缩放及字体设置。源码提交与运行版本未对应时明确说明，不能相互证明效果。

### 2. 列出覆盖范围

首次或全流程验收列页面 × 组件 × 交互动作 × 结果状态 × 端别清单；问题二次验收以原问题清单为范围。首页覆盖本次范围中的各类卡片，不能只看导航和页面骨架。按相关性检查默认、hover／按下、聚焦、选中与取消、展开与收起、输入与清空、上传与删除、禁用、加载、成功、失败、空态、异常和长内容等状态。

可交互组件不能只核对初始截图。应列出本次范围内真实存在的入口和动作，检查动作触发前、触发中、完成后及可逆操作后的界面；异步交互还需检查等待、成功、失败和达到上限等实际分支。没有对应设计状态或无法触发时，明确记录未覆盖依据，不能把默认态一致外推为全部交互态一致。

已查、依据不足、未覆盖的范围分别记录在覆盖说明中，不作为额外的问题状态；没有具体差异的未覆盖页面不虚构为问题。相同组件出现在不同端时独立核验，不把某端通过外推到全部端。

### 3. 读取设计依据

获取对应状态的当前设计参数和截图，保留 node 定位及读取日期。交互前后状态分别定位对应 frame、variant 或节点，不能用默认态设计代替 hover、选中、展开、上传后或禁用态。确认字体、颜色、行高、尺寸、间距、圆角、边框、图标大小与颜色、图像裁切和响应式规则；旧截图、相邻页面或历史 node 不能默认为当前规范。

图标作为独立检查项，核验宽高、比例、可见图形边界、颜色及透明度，并按本次覆盖范围核对默认、选中、按下、禁用等状态。区分图标可见尺寸、资源画布、承载容器与点击区域，不能用按钮或点击区域尺寸代替图标大小；颜色追踪实际资源、主题着色及状态覆盖后的生效值。

以 iOS 稿验收其他端时，共同视觉要求继续对照；平台差异需有设计确认或明确的平台规范依据。无依据的差异作为待设计确认候选，不能自行豁免，也不能仅因不同于 iOS 就断言为缺陷。

### 4. 追踪实际生效参数

从页面入口追到目标组件、状态分支、主题、资源、覆盖、布局和缩放。对可交互组件继续追踪“事件或手势处理 → 状态或数据更新 → 条件渲染／状态选择器 → 最终继承与覆盖后的样式”，并核对取消、关闭、删除或返回等逆向路径。优先确认实际引用的代码，排除死代码、未命中配置及不生效的默认值；存在事件处理函数不等于交互后样式已经正确。

分别标注声明值、结合条件推导的生效值、运行测量值。资源名不是数值；单个常量不能替代完整调用链。保留文件位置、完整提交号、条件及必要片段，不只截一行样式。

### 5. 判断差异与归属

保留双方原始单位及映射依据，不直接等同 CSS px、pt、dp/sp、vp/fp 或截图物理像素。源码验收按已解析的生效参数与设计要求判定；已确定的参数差异不必等截图才记录，根因不明时只保留具体疑点。

项目与端别决定开发团队，不重复设置一个含义相同的团队选择项。Hybrid 需同时记录发生端和实现归属：确认 H5 根因的新问题归社区前端，并注明发生的 App 端；归属未知保留观察端、标注待确认。历史问题不静默改端，补充关联和后续结论。

优先级参考：P0 为关键界面不可用或严重遮挡；P1 为明显影响阅读、视觉层级或主要布局；P2 为局部样式偏差。优先级不替代证据充分程度。

### 6. 准备设计师可核验的证据

首次发现默认提供实现侧与设计侧双图缩略图、同编号定位框、整页定位和原图入口；交互态问题的图片与设计节点必须对应同一动作后的同一状态，不能拿默认态截图证明交互态差异。源码细节折叠辅助。二次源码验收保留原问题图片和当前设计定位供核对，代码与资源解析作为本次修复依据；历史截图放原始记录，不当作修改后的效果。

前端原组件隔离运行标为 source-render，不能冒充完整产品运行图。声明完成运行视觉验收时要求对应版本运行截图。缺图不妨碍有充分源码依据的修复通过；依据不足的具体候选仍入总表，不伪造图片或测量。

### 7. 核验证据后集中追加报告

按上方阶段完成覆盖检查、多轮细节检查及证据核验，核对实现入口、生效参数与最终结论，检查过程留作内部依据，不给每轮单独生成报告。未完成的范围如实说明，不为提交校验编造轮次或新增数。

先查同项目历史问题，复用原编号；具体新增候选与确认问题都进入预览总表及批次，由用户判断是否忽略。新增问题初始处理状态统一为待处理，证据限制记录在详情；已忽略和未覆盖问题保持原状态。

按上方二次验收口径判定并更新状态。一次任务核完后集中提交结果；相同源码、设计和结论没有变化时不新增批次。状态、编号、历史及精简展示按报告契约执行。

交付多项目预览链接、覆盖范围、确认问题与候选的区别及验证结果。日常“发布”指更新该环境，具体版本按当次任务授权执行；不再默认追加一次正式站发布，不能把未审阅的新批次混入已授权版本。

## 维护方式

公共判定规则只在本文件维护；技术栈特有解析规则放各端参考；固定入口放 projects；证据与报告行为放 report。新经验先判断属于公共规则还是某端特例，再修改对应文件。新增端别时增加解析参考及路由，不复制整套主流程。

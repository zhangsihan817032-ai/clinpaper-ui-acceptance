# 统一设计验收主流程

以目标版本源码与当前设计稿为主要对比材料，用界面图片让设计师核验发现。分别记录源码参数差异、视觉复现、根因判断和修复结论；代码推导不能写成运行实测。

本 skill 是项目内维护的验收规范与参考入口，不代表已经实现各端自动解析器或接通全部仓库、构建环境。

后续工作仅在多项目预览进行，具体入口见 [项目与环境](references/projects.md)。走查、补图、登记、状态维护和报告交付均写入该环境；旧正式站与旧 ClinPaper 预览仅供历史核对，不默认同步或发布。

## 问题二次验收

用户要求复验、检查修复或二次验收时，默认核验目标源码与当前设计稿是否一致，不以真机、模拟器或运行截图作为通过的前置条件。只复查原问题及直接相关实现，追踪实际引用、资源定义、条件分支和覆盖关系；不能仅凭提交说明或变量名判定修复。

- 原问题维度已与设计一致：更新原编号为已解决，依据标为源码验收。
- 仍有明确差异：保持待处理，简述剩余差异。
- 源码、资源或设计依据无法确定：保持待处理，只写具体疑点；不能仅因缺运行截图判待复核。

已忽略及未检查的问题不改状态。用户另外要求真机视觉验收时，再取得目标版本运行图；源码结论不冒充运行实测。报告沿用现有问题和界面，按 [报告契约](references/report.md) 控制增量，不因复验追加装饰信息。

## 统一流程

### 1. 固定验收基线

记录项目、端别、目标版本、分支或标签及解析后的完整提交号、设计文件和具体 frame/node、页面与状态。版本由当次任务决定，不默认沿用历史版本。

运行图另记 App 构建号、实际部署或加载的 H5 版本、设备与系统、视口、像素尺寸、缩放及字体设置。源码提交与运行版本未对应时明确说明，不能相互证明效果。

### 2. 列出覆盖范围

首次或全流程验收列页面 × 组件 × 状态 × 端别清单；问题二次验收以原问题清单为范围。首页覆盖本次范围中的各类卡片，不能只看导航和页面骨架。按相关性检查默认、选中、禁用、加载、空态、异常和长内容等状态。

已查、待复核、未覆盖分别记录；没有具体差异的未覆盖页面不虚构为问题。相同组件出现在不同端时独立核验，不把某端通过外推到全部端。

### 3. 读取设计依据

获取对应状态的当前设计参数和截图，保留 node 定位及读取日期。确认字体、颜色、行高、尺寸、间距、圆角、边框、图像裁切和响应式规则；旧截图、相邻页面或历史 node 不能默认为当前规范。

以 iOS 稿验收其他端时，共同视觉要求继续对照；平台差异需有设计确认或明确的平台规范依据。无依据的差异作为待设计确认候选，不能自行豁免，也不能仅因不同于 iOS 就断言为缺陷。

### 4. 追踪实际生效参数

从页面入口追到目标组件、状态分支、主题、资源、覆盖、布局和缩放。优先确认实际引用的代码，排除死代码、未命中配置及不生效的默认值。

分别标注声明值、结合条件推导的生效值、运行测量值。资源名不是数值；单个常量不能替代完整调用链。保留文件位置、完整提交号、条件及必要片段，不只截一行样式。

### 5. 判断差异与归属

保留双方原始单位及映射依据，不直接等同 CSS px、pt、dp/sp、vp/fp 或截图物理像素。源码验收按已解析的生效参数与设计要求判定；已确定的参数差异不必等截图才记录，根因不明时只保留具体疑点。

项目与端别决定开发团队，不重复设置一个含义相同的团队选择项。Hybrid 需同时记录发生端和实现归属：确认 H5 根因的新问题归社区前端，并注明发生的 App 端；归属未知保留观察端、标注待确认。历史问题不静默改端，补充关联和后续结论。

优先级参考：P0 为关键界面不可用或严重遮挡；P1 为明显影响阅读、视觉层级或主要布局；P2 为局部样式偏差。优先级不替代证据充分程度。

### 6. 准备设计师可核验的证据

首次发现默认提供实现侧与设计侧双图缩略图、同编号定位框、整页定位和原图入口，源码细节折叠辅助。二次源码验收保留原问题图片和当前设计定位供核对，代码与资源解析作为本次修复依据；历史截图放原始记录，不当作修改后的效果。

前端原组件隔离运行标为 source-render，不能冒充完整产品运行图。声明完成运行视觉验收时要求对应版本运行截图。缺图不妨碍有充分源码依据的修复通过；依据不足的具体候选仍入总表，不伪造图片或测量。

### 7. 复核并追加报告

核对实现入口、生效参数与最终结论，检查过程留作内部依据，不给每轮单独生成报告。未完成的范围如实说明，不为提交校验编造轮次或新增数。

先查同项目历史问题，复用原编号；具体新增候选与确认问题都进入预览总表及批次，由用户判断是否忽略。新候选在 issue 和 finding 均标 reviewState 为“待复核”，初始处理状态为待处理；已忽略和未覆盖问题保持原状态。

按上方二次验收口径判定并更新状态。一次任务核完后集中提交结果；相同源码、设计和结论没有变化时不新增批次。状态、编号、历史及精简展示按报告契约执行。

交付多项目预览链接、覆盖范围、确认问题与候选的区别及验证结果。日常“发布”指更新该环境，具体版本按当次任务授权执行；不再默认追加一次正式站发布，不能把未审阅的新批次混入已授权版本。

## 维护方式

公共判定规则只在本文件维护；技术栈特有解析规则放各端参考；固定入口放 projects；证据与报告行为放 report。新经验先判断属于公共规则还是某端特例，再修改对应文件。新增端别时增加解析参考及路由，不复制整套主流程。
